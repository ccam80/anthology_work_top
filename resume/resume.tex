\section{Cubie}
Cubie is an open-source
Python project which performs numerical integration on consumer NVIDIA GPUs.
My research interest was in large-scale parameter studies for real-time estimation
of physiological parameters using a Bayesian approach. This would have been a
pointless toy if the simulation could not be completed faster than real-time, so
I built Cubie to do it.

\subsection{GPU Kernels and Optimisation}

Numerical integration is inherently sequential, as each sample depends on the previous one.
Cubie parallelises across parameter sets and initial conditions, running a full time-integration per thread.
The workload can be memory- or compute-bound, depending on the user-supplied set of equations to solve.
Occupancy is limited by registers for most non-toy problems, and performance in these kernels is memory-bound through spills.
In no-spill kernels, performance is either limited by math-required control flow or floating point pipeline throughput.

Cubie kernels are JIT-compiled through
\mbox{numba-cuda-mlir}, which allows dynamic optimisations based on a user's problem set.
Cubie's source code is written in Python, but typing and use of CUDA primitives is explicit and carefully managed.
Cubie ``goes fast'' due to algorithm design, operation scheduling, memory placement, and dynamic/heuristic optimisations.

Building Cubie has taken me deep into the inner workings of NVIDIA GPUs. I have a strong understanding of:
\begin{itemize}
  \item Memory hierarchy and management
  \item Warp scheduling and occupancy
  \item Nsight profiling tools and bottleneck identification
  \item Kernel optimization techniques
\end{itemize}


In my (draft, pending publishing) comparisons Cubie offers a 10,000$\times$ speedup
over general-use programs like MATLAB and SciPy, and 100$\times$ speedup over its nearest competitor, DiffEqGPU.jl
from the SciML team at MIT.
