\section{Cubie}
% \subsection{What and why}
Cubie is an open-source Python project which performs numerical integration on consumer NVIDIA GPUs.
Its goal is to put high-performance computing in the hands of everyday researchers and engineers.
My research called for simulations of cells under a range of possible conditions for a real-time application, 
and it would have been a pointless toy if the simulation could not be completed faster than real-time, so I built Cubie to do it.

% \subsection{Why it's relevant}
\textbf{My work on Cubie should tick every "you should bring" box in the invitation for this role.}

Numerical integration algorithms are large and sequential, as each sample depends on the last.
Cubie runs a whole integration in one thread, as experimentation ruled out data-parallel approaches.
Cubie's kernels can be memory- or compute-bound, depending on user-supplied equations to solve.
With ``easy'' levers like coalescing memory accesses and memory tiling exhausted, performance
was hard-fought against Nsight profiling tools.

In (draft, pending publishing) benchmark comparisons, Cubie is 10,000$\times$ faster than equivalent CPU implementations (SciPy, MATLAB), and 100x faster than other GPU implementations (DiffEqGPU.jl).
If my kernel optimization skills are not at expert level across kernel design globally, I can at least confirm that they're at the top end of the domain-specific range! 

Cubie needs to go fast, but it is primarily a tool for generating accurate numbers.
Correctness needed verification at every internal stage, which required deliberate instrumentation to validate.

I now use agentic AI to write almost every line of code.
In this specialised code base, AI agents are usually wrong.
My interaction with code is through PR reviews and agent sessions, where every line and behaviour needs to be questioned, scrutinized and validated.
