\section{Cubie --- GPU numerical integration}
{\small\color{muted}\href{https://github.com/cubiepy/cubie}{github.com/cubiepy/cubie}\par}
I built Cubie, an open-source Python ODE solver for consumer NVIDIA GPUs, to support
electrophysiology simulations for a real-time application.

Current benchmarks (draft, unpublished) show \textbf{10,000$\times$ speedup}
over CPU implementations (SciPy, MATLAB) and \textbf{100$\times$}
over the nearest GPU competitor, DiffEqGPU.jl, on real-world problems.
{\small\color{muted}\href{https://github.com/ccam80/GPUODEBenchmarks}{Benchmarks: github.com/ccam80/GPUODEBenchmarks}\par}

After adapting the algorithms for CUDA and addressing tiling and memory
placement, I improved performance by:

\begin{itemize}
  \item using NVIDIA profiling tools to trace bottlenecks and stalls
    to individual instructions;
  \item using measured instruction counts to choose loop unrolling
    that fits the instruction cache;
  \item reducing occupancy to lower L2 cache misses;
  \item reordering and fusing operations across each kernel to shorten
    live ranges and reduce register spilling; and
  \item placing buffers in shared or local memory based on working-set size,
    trading guaranteed on-chip storage against reliance on caches.
\end{itemize}

Cubie's numerical correctness is critical to its use as a scientific tool.
To maintain correctness as the codebase evolves, I:

\begin{itemize}
  \item test numerical results against known references and custom CPU harnesses;
  \item review every pull request line by line, checking for errors in AI-generated code; and
  \item require automated correctness checks and a ratcheting performance benchmark
    before approving each pull request.
\end{itemize}
